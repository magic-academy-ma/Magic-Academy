# /pr-review

현재 브랜치의 diff를 분석해 태그 기반 리뷰 코멘트를 생성한다.

## 태그 규칙

모든 코멘트는 반드시 아래 태그 중 하나로 시작한다. 태그 없는 코멘트는 작성하지 않는다.

| 태그 | 의미 |
|------|------|
| `[Must]` | 반드시 수정해야 하는 부분 |
| `[Question]` | 질문 또는 확인이 필요한 부분 |
| `[Suggest]` | 개선 제안 (선택 사항) |
| `[Nit]` | 사소한 수정 (스타일, 오타 등) |
| `[Good]` | 좋은 구현 또는 유지하면 좋은 부분 |

## 실행 순서

1. `git diff develop...HEAD` 또는 사용자가 지정한 범위로 diff를 가져온다
2. 변경 파일 목록과 변경 규모를 파악한다
3. 아래 관점으로 검토한다:
   - 작업 범위 준수 — 요청 범위 밖의 변경이 포함됐는가
   - 스펙 준수 — `04-feature-specs/`의 스펙과 일치하는가
   - 도메인 모델 일치 — `02-domain/`의 모델과 어긋나지 않는가
   - 컨벤션 준수 — `05-team-rules/`의 코드 스타일·브랜치·커밋 규칙
   - 보안 — 시크릿·개인정보가 포함됐는가 (Public 저장소)

## 출력 형식

```
## PR 리뷰 — {브랜치명}

### 변경 요약
- 파일 N개 변경, +M줄 추가, -K줄 삭제

### 리뷰 코멘트

**{파일명}:{줄번호}**
[태그] 코멘트 내용

...

### 종합 의견
전체적인 판단과 필수 수정 항목 요약.
```
