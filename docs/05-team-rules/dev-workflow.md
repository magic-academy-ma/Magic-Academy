# AI 개발 워크플로우

AI는 로컬 작업을 자율적으로 수행하되, GitHub·Confluence·Discord 등 외부에 영향을 주는 작업은 사람이 최종 통제한다. 이 정책은 AI 사용 컨벤션의 원칙을 실제 개발 절차에 적용한다.

## 개발 사이클별 역할

### Git 작업 (기능 추가·버그 수정)

| 단계 | AI 역할 | 제약 |
|------|---------|------|
| Issue 생성 | 제목·본문 초안 작성 | 초안 → 승인 → 생성 |
| PR Draft 생성 | 제목·본문 초안 작성 | 초안 → 승인 → 생성 |
| 구현 | 테스트를 먼저 작성한 뒤 구현 | 로컬 자율 |
| 커밋 | 메시지 초안 작성 및 커밋 준비 | 승인 후 실행 |
| PR Draft → Ready | 전환 의도 확인 | 승인 후 실행 |
| PR 리뷰 | 태그가 포함된 코멘트 초안 작성 | 초안 → 승인 → 게시 |

### 문서·설계 작업

| 단계 | AI 역할 | 제약 |
|------|---------|------|
| 초안 작성 | 설계 문서·Confluence 초안 작성 | 로컬 자율 |
| 팀 검토 | 비공개 Confluence Draft 생성 | Draft 생성 → 팀 확인 → 승인 → Publish |

## 외부 게시 승인 정책

### 로컬 자율

다음 작업은 승인 없이 수행할 수 있다.

- 파일 수정·생성·삭제
- 로컬 테스트 실행
- 코드 분석 및 설계 초안 작성

### 승인 후 실행

행위 자체에 대한 승인을 받은 뒤 실행한다.

- `git commit`
- `git push`
- PR Draft → Ready 전환
- Confluence Draft → Publish

### 초안 → 승인 → 실행

내용 전체를 먼저 보여주고 승인받은 뒤 생성하거나 게시한다.

- GitHub Issue 생성
- GitHub Draft PR 생성
- PR 리뷰 코멘트 게시
- Confluence Draft 페이지 생성 및 수정
- Discord 공지

## 외부 액션 절차

| 액션 | 절차 |
|------|------|
| GitHub Issue | 제목·본문 초안 출력 → 승인 → 생성 |
| GitHub Draft PR | 제목·본문 초안 출력 → 승인 → 생성 |
| PR Draft → Ready | 전환 의도 출력 → 승인 → 전환 |
| PR 리뷰 코멘트 | 태그를 포함한 초안 출력 → 승인 → 게시 |
| git commit | staged diff 확인 → 커밋 메시지 초안 출력 → 승인 → 커밋 |
| git push | 대상 브랜치·커밋 확인 → 승인 → push |
| Confluence 페이지 생성 | 로컬 초안 작성 → 비공개 Draft 생성 → 팀 확인 → 승인 → Publish |
| Confluence 페이지 수정 | 수정 내용 초안 출력 → 승인 → 업데이트 |
| Discord 공지 | 공지 초안 출력 → 승인 → 전송 |

## 적용 원칙

- AI 결과물은 사람이 검토하고, 핵심 아키텍처·보안·인증·권한·최종 기획 결정은 팀원이 직접 결정한다.
- API Key, 비밀번호, 개인 계정 정보, 민감 개인정보, 공개 불가 자료는 AI에 제공하지 않는다.
- 외부 게시 전에는 대상과 내용을 명확히 확인한다.
