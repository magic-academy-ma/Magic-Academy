# FR-TBD 업적 목록

## 1. 목적

스토리모드와 자유 모드의 업적을 한 곳에 모은다. 이 문서가 업적 이름·종류·달성 조건의 기준이다. 챕터 업적의 세부 판정은 각 챕터 문서를 따른다.

## 2. 범위

**포함**
- 전체 업적 목록(ID, 이름, 종류, 달성 조건)
- 계정별 업적 저장과 조회, MyPage 업적 화면(§6)
- 스토리모드 챕터 판정 결과를 지급으로 연결하는 일(§6)

**제외**
- 업적 달성 알림
- 자유 모드의 판정 결과를 지급으로 연결하는 일(별도 이슈)
- 자유 모드 업적의 세부 판정 기준

## 3. 업적 종류

| 종류 | 뜻 |
| --- | --- |
| 진행 | 챕터·스토리를 끝까지 진행하면 얻는다 |
| 관찰 | 플레이어가 무언가를 보거나 알아내면 얻는다 |
| 개입 | 플레이어의 개입(또는 개입하지 않음)이 만든 결과로 얻는다 |
| 결과 | 챕터가 특정 결말로 끝나면 얻는다 |

## 6. 저장과 조회

- 카탈로그: `backend/app/domain/achievements.py`. 이 문서의 목록과 순서를 그대로 옮긴다.
- 저장: `user_achievements` 테이블. 계정·업적 쌍마다 한 행만 두고, 최초 달성 시각(`achieved_at`)을 유지한다.
- 지급: `services/achievements.grant_achievements`. 이미 달성한 업적은 무시하고 이번에 처음 달성한 ID만 돌려준다. 카탈로그에 없는 ID는 거부한다. 호출한 쪽 트랜잭션 안에서 실행하고 직접 commit하지 않는다.
- 조회: `GET /v1/achievements`. 카탈로그 순서대로 전체 업적과 내 달성 여부·달성 시각을 돌려준다.
- 스토리모드 지급 시점: 챕터를 완료할 때(`POST /v1/story/{id}/chapter/complete`, `story_mode.complete_current_chapter`). 챕터 기록 저장과 업적 지급을 한 transaction으로 commit한다.
  - 챕터 클리어(`CHAPTERn_CLEAR`)는 run이 중단(`ABORTED`) 없이 끝났을 때다. 끝나지 않았거나 중단된 run은 업적을 하나도 지급하지 않는다.
  - 「우유부단하시네요」는 그 챕터의 개입 기록으로 판정해 함께 지급한다.
  - 엔딩 스토리: CHAPTER 4를 완료해 FINAL 단계에 도달하면 `ENDING_UNLOCKED`, 학기가 완료되면 `ENDING_CLEAR`를 지급한다. 지금은 FINAL 도달과 학기 완료가 같은 시점이라 두 업적이 함께 지급된다.
  - 완료 응답의 `new_achievements`에 이번에 처음 달성한 업적만 담고, 다음 화면(다음 챕터 도입 또는 FINAL) 상단에 「업적 달성」으로 보여 준다.
- 화면: MyPage 메뉴의 '업적' 탭. 그룹별로 보여 주고, 달성하지 않은 업적도 조건과 함께 흐리게 보여 준다.
