# Slice 7 Task 5 — 외부 사용자 검증 가이드

> 이 문서는 외부 사용자가 배포 환경에서 공유·검색·가져오기·실행 흐름을
> 검증할 수 있도록 안내한다. 실제 Railway 배포는 아직 완료되지 않았다
> (`docs/04-feature-specs/slice-7-railway-deployment.md` §1 참고) — 배포
> URL이 채워지기 전까지는 이 가이드로 실제 외부 검증을 시작할 수 없다.

## 0. 사전 준비물 (배포 담당자가 채운다)

- 배포된 Frontend URL: `<TBD — Railway 배포 완료 후 기입>`
- 배포된 Backend API URL: `<TBD>`
- 배포 환경 상태: `GET <backend URL>/health` 가 `{"status":"ok","database":"ok","migration":"ok"}` 를 반환하는지 확인 후 이 문서에 확인 날짜를 기록한다.

## 1. 테스트 계정

- 외부 검증자는 **운영 실사용자 계정이 아닌 전용 테스트 계정**을 새로 만든다.
  배포된 Frontend에서 "계정 만들기"로 직접 가입한다(아이디/표시 이름/비밀번호
  자유 설정, 8자 이상).
- 최소 2개 계정을 준비한다(A: 공유하는 사람, B: 가져오는 사람) — 소유권·권한
  검증에는 서로 다른 사용자가 필요하다.
- 실제 개인정보(실명, 개인 이메일, 재사용 비밀번호)를 사용하지 않는다.
- 테스트 계정의 비밀번호는 이 문서나 피드백 양식에 기록하지 않는다.

## 2. 권한 기준 (검증 중 계속 참고)

| visibility | 소유자 조회 | 공유 ID 직접 접근 | 공개 목록·검색 | 다른 사용자 가져오기 |
| --- | ---: | ---: | ---: | ---: |
| `private` | 허용 | 불가 | 불가 | 불가 |
| `unlisted` | 허용 | 허용 | 불가 | 허용 |
| `public` | 허용 | 허용 | 허용 | 허용 |

접근할 수 없는 공유와 취소된 공유는 모두 **404**로 응답한다(존재 여부를
숨기기 위해 403이 아니라 404를 쓴다 — 계약서 §3).

## 3. Golden Path (정상 흐름)

1. **계정 A**로 로그인 → 새 Simulation 생성(자동으로 6명 Agent 배정, 시작 전
   `ready` 상태).
2. 관리 탭에서 **공유** 탭을 열고 공개 범위를 `public`으로 선택해 공유 생성.
   → 화면에 공유 ID가 표시되는지 확인.
3. **계정 B**로 로그인(다른 브라우저 세션 또는 시크릿 창) → 헤더의
   **공유 설정 둘러보기** 버튼 클릭.
4. 검색창에 계정 A가 붙인 제목의 일부를 입력해 검색 → 목록에 나타나는지
   확인.
5. 목록에서 항목을 선택 → 상세 화면에서 Student/Professor/Organization 수
   요약이 보이는지 확인.
6. **이 설정 가져오기** → 확인 다이얼로그에서 **가져오기 확인**.
7. 가져오기 성공 후 새 Simulation으로 자동 이동하는지, 화면에 "가져온
   Simulation" 표시가 보이는지 확인.
8. 가져온 Simulation에서 Tick을 1회 실행해 정상적으로 진행되는지 확인
   (가져오기 자체는 Tick/LLM을 실행하지 않지만, 가져온 결과가 이후 정상
   실행 가능해야 한다).
9. 계정 A로 돌아가 원래 Simulation의 이름·상태·Tick이 그대로인지 확인(원본
   불변).

## 4. 실패 시나리오 (반드시 확인)

| 시나리오 | 수행 방법 | 기대 결과 |
| --- | --- | --- |
| private 비노출 | 계정 A가 `private`로 공유 생성 → 계정 B가 공개 목록/검색에서 확인 | 목록에 나타나지 않음 |
| private 직접 접근 차단 | 계정 A의 private 공유 ID를 계정 B가 URL로 직접 접근(가능하다면) | 404 |
| unlisted 검색 비노출 | `unlisted`로 공유 생성 → 계정 B가 목록/검색에서 확인 | 목록에 나타나지 않음 |
| unlisted 직접 접근 | 계정 B가 정확한 공유 ID로 상세 조회 | 200, 정상 조회 |
| 취소된 공유 | 계정 A가 공유 취소 → 계정 B가 이전에 열어둔 상세/가져오기 재시도 | 404 |
| 실행 중 Simulation 공유 시도 | Tick이 1회 이상 진행된 Simulation을 공유 시도 | 409, "공유할 수 없다"는 안내 |
| 동일 가져오기 재시도 | 가져오기 버튼을 네트워크 지연 중 다시 눌러보거나 새로고침 후 같은 공유를 다시 가져오기 | 새 Simulation이 중복 생성되지 않음(백엔드가 같은 요청을 같은 결과로 처리) |
| 잘못된 공유 ID | 존재하지 않는 UUID로 상세 조회 URL 직접 접근 | 404 |

내부적으로는 아래도 자동화 테스트로 이미 검증되어 있다(외부 검증자가 직접
서버 로그/DB를 볼 필요는 없음, 참고용):
- idempotency 충돌(같은 key로 다른 공유 요청) → 409
- 가져오기 transaction 중 실패 시 전체 rollback(부분 생성 없음)
- 지원하지 않는 schema_version → 422
- 가져오기 중 Runtime·LLM·Tick 호출 0회

## 5. 관찰해야 할 것

- 오류가 발생했을 때 화면에 **이해 가능한 한국어 메시지**가 뜨는지(빈 화면,
  영어 stack trace, 무한 로딩이 아닌지).
- 로딩 상태(스피너/텍스트)가 명확한지.
- 가져온 Simulation과 원본 Simulation을 화면에서 구분할 수 있는지.
- 공유·가져오기 흐름을 문서 없이도 대략 유추할 수 있는지(직관성).

## 6. 피드백 양식

아래 항목을 채워 이슈 코멘트 또는 별도 공유 문서로 제출한다. **실제
비밀번호/개인정보는 적지 않는다.**

```
검증자:
검증 일시:
사용한 계정 역할 (A=공유자 / B=가져오는 사람):
브라우저/환경:

1) 어떤 단계에서 무엇을 했는가:
2) 기대한 동작:
3) 실제 동작(스크린샷/오류 메시지 텍스트 가능하면 첨부):
4) 심각도 체감 (Must — 진행 불가/보안 문제 / Optional — 불편하지만 우회 가능):
5) 재현 가능 여부 (항상 / 가끔 / 1회):
```

## 7. Must vs Optional 분류 기준

- **Must**: Golden Path 또는 §4 실패 시나리오 중 하나라도 기대와 다르게
  동작. 특히 다음은 항상 Must로 분류한다.
  - private/unlisted 정보가 목록·검색에 노출됨
  - 취소되었거나 존재하지 않는 공유가 200/그 외 정상 응답을 반환함
  - 가져오기가 원본을 변경하거나 새 Simulation을 중복 생성함
  - 가져오기 중 실제로 Tick/LLM이 실행되는 것으로 보임(응답 지연이 비정상적으로
    길거나 과금 로그가 보이는 등)
  - 인증 없이 소유자 전용 동작(공유 생성/취소)이 수행됨
- **Optional**: 문구가 어색함, 레이아웃이 좁은 화면에서 깨짐, 있으면 좋을
  추가 필터/정렬 등 — Slice 7 PASS의 blocker로 취급하지 않는다.
