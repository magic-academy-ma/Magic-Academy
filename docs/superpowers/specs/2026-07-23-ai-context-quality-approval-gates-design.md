# AI Context 품질 기준 및 사람의 승인 지점 설계

## 1. 목적 및 스코프

이 설계는 Magic Academy 저장소의 AI-native 개발 환경에서 두 가지 공백을 채운다.

1. **AI context 품질 기준** — AI가 작업 시작 전 자신의 컨텍스트가 충분한지 판단하고, 팀원이 docs를 작성·갱신할 때 품질을 점검하는 기준
2. **사람의 승인 지점** — AGENTS.md의 기존 "승인 필요 작업" 목록에 판단 원칙·흐름·처리 방법 추가

### 현재 상태 (as-is)

| 이미 있는 것 | 없는 것 |
|------------|--------|
| 작업 유형별 파일 로딩 범위 (`context-scope.md`) | context가 충분한지 판단하는 품질 기준 |
| AI 사용 가능/주의/금지 작업 분류 (`ai-usage.md`) | 작업 흐름상 승인 게이트 위치 |
| 승인 필요 작업 목록 (`AGENTS.md`) | 목록 밖 상황에서의 판단 원칙, 승인 후 처리 방법 |

### 스코프 밖

- context-scope.md의 로딩 범위 변경 — 품질 기준 파일 등록만 추가
- AGENTS.md의 기존 목록·형식 변경 — 앞에 삽입하는 방식으로 확장
- ai-usage.md 수정 없음

## 3. `context-quality.md` 설계

### 위치 및 분류

- 파일: `docs/00-start-here/context-quality.md`
- context-scope 분류: **Always Load**
- 목표 토큰: ~200토큰 (짧고 체크리스트 중심)

### 구조

두 파트로 구성한다. 독자가 AI일 때와 팀원일 때 각각 필요한 내용이 다르므로 파트를 명시적으로 구분한다.

#### 파트 1 — AI 자가 점검 체크리스트

작업 시작 시 AI가 확인한다. 실패 항목이 하나라도 있으면 작업 전 사용자에게 알리고 확인 요청.

```
□ 완전성: context-scope.md 기준으로 이 작업 유형에 필요한 파일을 모두 로드했는가
□ 미정 확인: what-is-pending.md에서 현재 작업과 교차하는 미정 항목을 확인했는가
□ 충돌 없음: 로드한 문서 간 서로 모순되는 내용이 없는가
□ 민감 정보: 로드한 컨텍스트에 시크릿·개인정보가 포함되지 않았는가
```

**미달 처리**: 실패 항목을 나열하고 "작업을 시작하기 전에 확인이 필요합니다" 형식으로 사용자에게 알린다. 추측하거나 빠진 컨텍스트를 가정해서 진행하지 않는다.

#### 파트 2 — 문서 관리자용 품질 기준

팀원이 docs를 작성·갱신·PR 머지 전 확인한다.

```
□ frontmatter: title, status, updated, source_updated 필드가 모두 채워져 있는가
□ 미정 명시: 확정되지 않은 내용에 [미정] 또는 pending 표시가 있는가
□ 크로스링크: 관련 문서를 상대 경로로 참조하고 있는가
□ 토큰 효율: 불필요한 중복·설명·예시 없이 핵심만 담겨 있는가
□ 민감 정보: PUBLIC 저장소 기준에 맞게 분류됐는가 (_meta/SYNC.md 분류 정책 참조)
```

## 4. AGENTS.md 승인 섹션 확장 설계

기존 "승인 필요 작업" 섹션의 **`**Git**` 블록 바로 위에** 세 블록을 삽입한다. 기존 목록과 형식은 변경하지 않는다.

### 삽입 블록 1 — 판단 3원칙

목록에 없는 상황에서 AI가 스스로 판단하는 기준. 아래 중 하나라도 해당하면 승인 요청.

```
1. 되돌릴 수 없는가    (예: 파일 삭제, DB drop, force push)
2. 요청 범위를 벗어났는가  (예: A 수정 요청인데 B도 건드려야 할 때)
3. 외부에 영향을 주는가  (예: push, PR 생성, 외부 API 쓰기 호출)
```

### 삽입 블록 2 — 작업 흐름상 승인 게이트

언제 멈추고 물어봐야 하는가:

```
시작 전:   작업 범위가 두 가지 이상으로 해석될 때
도중:      예상치 못한 상황이 생겨 범위를 넘어야 할 때
완료 전:   돌이키기 어려운 변경이 포함될 때 (커밋, push, 파일 삭제 등)
```

### 삽입 블록 3 — 승인 후 처리 원칙

```
- 승인받은 범위만 수행한다. 연관 작업이 생겨도 별도 승인을 받는다.
- 승인 도중 새로운 승인 필요 상황이 생기면 작업을 멈추고 다시 요청한다.
- 거절 시: 대안을 제안하거나 작업을 중단한다. 우회하지 않는다.
```
