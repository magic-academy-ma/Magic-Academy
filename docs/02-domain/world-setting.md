# [전제 조건] Magic Academy 세계관 설정

## 0. 개요 및 목적

이 문서는 Magic Academy MVP의 세계관, Agent 구성, 학교 구조와 시뮬레이션 전제를 정의한다.

- **목적**: 기획·Agent·Runtime·UI 문서가 동일한 세계관과 규모·성격·시간 기준을 사용하도록 한다.
- **범위**: MVP의 Student·Professor·User Persona, 학교·Event·관계·Tick·공간 전제를 다룬다.

## 1. Magic Academy 개요

마법을 배우는 대학교. 마법사 사회의 축소판으로, 서로 다른 성향과 배경을 가진 학생들이 공존하며 관계를 맺고 사건을 만들어가는 공간이다.

**설계 원칙**

- Agent 수가 적어도 각자가 서로 다른 집단·성향을 대표하여 사회적 다양성 확보 (국회형 구성)
- 적은 수로도 갈등·협력·배신·우정이 자연스럽게 발생하도록 설계

**세계관 레퍼런스:** 해리포터

**시스템 레퍼런스:** The Sims · AI Town · 슈퍼월드박스 · Sandbox game · Generative Agents (Stanford, 2023)

## 2. Agent 구성

| 구분 | 수 | 행동 방식 | 비고 |
| --- | --- | --- | --- |
| 학생 Agent | 5명 | 자율 행동 | 기본 학생 4명(성향 유형별 각 1명) + User Persona 1명 포함. User Persona는 시작 전 성격 설정까지만 개입 가능 |
| 교수 Agent | 1명 | 수업 진행 및 자율 행동 | 학생 전원과 같은 전공 소속 |
| **총합** | **6명** | | |

### 2.1 학생 Agent 공통 구조

학생 Agent는 매 tick 현재 상태값, 성격, Memory, 다른 Agent와의 관계, 현재 위치, 진행 중인 이벤트를 바탕으로 행동을 결정한다.

Intent 종류 (TALK / MOVE / STUDY / REST / EAT / PARTICIPATE / AVOID), 상태값 (배고픔·피로도·스트레스·만족도·기분) 정의, Memory 규칙 (상한 10개, 유형 4종, 검색, 초과 처리): `docs/03-system-design/agent-runtime.md` 참조.  
상태값 범위 및 설명: `docs/02-domain/agents.md §공통 내부 상태` 참조.

### 2.2 기본 Student Agent 생성

1단계 MVP의 Student 5명은 [[Spec] Student Agent 초기값](https://jehye.atlassian.net/wiki/spaces/MA/pages/19496962)의 고정 fixture를 사용한다.

| 이름 | 최초 MBTI | 대표 역할 |
| --- | --- | --- |
| 아델 | ISTJ | 규칙 준수와 팀 안정 |
| 레오 | ESTP | 행동 촉발과 현실적 해결 |
| 리아 | INFP | 가치 충돌과 공감 |
| 카이 | ENTJ | 계획 수립과 목표 추진 |
| 세라 | ESFJ | 관계 연결과 갈등 중재 |

최초에는 MBTI 5종을 하나씩 배정한다. User Persona 설정 이후에는 MBTI 중복과 특정 MBTI 부재를 허용한다. 같은 fixture·성격 규칙 버전과 입력은 같은 초기값을 생성해야 한다.

### 2.3 성격 수치

학생 Agent의 성격은 MBTI 유형 1개와 Big Five 5개 값으로 구성한다.

- MBTI는 말투, 정보 인식 방식, 판단 방식, 생활 스타일을 제공하는 정성적 지침이다.
- Big Five는 행동 후보의 선호도와 표현 강도를 조절하는 연속형 값이다.
- Big Five의 UI·API·DB 범위는 `-50~+50`, 조절 단위는 `5`다.
- MBTI별 기본값·허용 범위는 [[Policy] MBTI → Big Five 초기값 및 허용 범위](https://jehye.atlassian.net/wiki/spaces/MA/pages/21791106)를 따른다.
- 같은 성향을 MBTI와 Big Five로 이중 수치 가산하지 않는다.

| 성격 수치 | 낮은 경우 | 높은 경우 | 주요 영향 |
| --- | --- | --- | --- |
| 개방성 | 익숙하고 실용적인 행동 선호 | 새로운 마법과 사건 선호 | 탐험, 새로운 사건 참여 |
| 성실성 | 유연하고 즉흥적인 선택 선호 | 계획과 규칙을 중요하게 생각함 | 수업, 시험, 과제 참여 |
| 외향성 | 혼자 또는 소수 행동 선호 | 다른 Agent와의 상호작용 선호 | 대화 및 만남 |
| 우호성 | 직설적 판단과 논쟁적 선택 선호 | 협력하고 타인을 배려함 | 협력, 갈등, 화해 |
| 정서 안정성 | 스트레스와 사건에 민감함 | 압박 속에서도 비교적 안정적임 | 스트레스·기분 대응 |

성격은 행동을 직접 결정하는 절대 조건이 아니다. 상태·관계·Memory·일정·Event와 함께 행동 후보에 영향을 준다.

### 2.4 User Persona Agent

User Persona는 Student 5명 중 사용자가 선택한 기존 Student 1명이다. 새 Agent를 추가하지 않는다.

1. 기존 Student 한 명을 선택한다.
2. ISTJ, ESTP, INFP, ENTJ, ESFJ 중 MBTI 하나를 선택한다.
3. 해당 MBTI의 Big Five 기본값과 허용 범위를 적용한다.
4. 사용자는 허용 범위 안에서 `5` 단위 슬라이더로 값을 조절한다.
5. MBTI를 다시 선택하면 Big Five 5개 값을 새 기본값으로 전부 초기화한다.
6. 설정 후 이름·학년·성별·관심 분야는 유지하고 MBTI·Big Five·성격 설명·성격 관련 Memory를 갱신한다.
7. 시뮬레이션 시작 이후에는 성격을 변경하거나 행동·대화를 직접 명령할 수 없다.

설정 후 같은 MBTI가 여러 명이 되거나 특정 MBTI가 없어져도 허용한다. User Persona의 상태값, 일반 Memory, 관계와 행동 결정 방식은 다른 Student와 동일하다.

### 2.5 Professor Agent

Professor Agent는 학생 전원과 동일한 전공에 소속되며, 수업 이벤트를 진행하고 학생을 평가한다.

Professor Agent도 학생과 동일한 상태값, Memory, 성격, 관계 데이터를 보유한다. 공통 데이터 구조를 사용하여 Agent 종류에 따른 별도 예외 처리를 최소화한다.

다만 학생 Agent와 달리 다음 행동에 높은 우선순위를 가진다.

- 정해진 시간에 CLASS 이벤트 진행
- 학생의 수업 참여 및 행동 관찰
- 시험 및 과제 평가
- 연구실에서 학생과 개별 면담
- 학생의 행동에 따른 상벌점 부여

Professor Agent와 학생 간에도 호감도, 친밀도, 신뢰도, 긴장도 등의 관계 수치가 형성된다. 교수의 학생 평가와 관계 수치는 EXAM, 장학금, 개별 면담 이벤트 등에 영향을 줄 수 있다.

교수는 모든 tick에서 반드시 수업을 진행하지 않는다. 수업 일정이 있는 tick에는 CLASS 이벤트를 우선 수행하고, 그 외 시간에는 연구, 휴식, 이동, 학생 면담 등의 행동을 선택한다.

## 3. 학교 구조

### MVP에서는 복수 전공과 전공·교양 수업을 지원한다.

각 Student Agent는 하나의 주전공에 소속된다. 전공 수업은 전공·학년·수강 조건을 따르고, 교양 수업은 전공과 무관하게 여러 전공의 Agent가 함께 수강할 수 있다. 구체적인 전공 수와 Student 배분은 fixture에서 정한다.

### 3.1 소속 구성

| 소속 종류 | 수 | 구성 | MVP 포함 여부 |
| --- | --- | --- | --- |
| 전공 | 복수 | Student Agent는 하나의 주전공에 소속 | 포함 |
| 기숙사 조직 | 없음 | 공간으로만 기숙사 사용 | 미포함 |
| 동아리 | 없음 | 추후 Agent 확장 시 추가 | 미포함 |
| 총학생회 | 없음 | 추후 Agent 확장 시 추가 | 미포함 |

MVP의 기숙사는 Agent의 공식 소속이 아닌 생활 공간으로만 사용한다.

동아리는 Student Agent 10명의 2단계에서 추가한다. 기숙사 조직과 총학생회는 Student Agent 20명의 3단계에서 추가한다.

### 3.2 전공 및 교양 수업 구성

MVP는 복수 전공을 지원하며, 각 Student Agent는 하나의 주전공을 가진다. 전공별 명칭·담당 교수·Student 배분은 fixture에서 정의한다.

| 수업 유형 | 수강 기준 | 예시 |
| --- | --- | --- |
| 전공 수업 | 전공·학년·수강 조건을 만족한 Agent | 변환 마법 실습, 방어 마법 이론 |
| 교양 수업 | 전공과 무관하게 AcademicScheduleSnapshot의 수강 Agent 목록에 포함된 Agent | 마법사 윤리, 마법 역사 |

교양 수업은 서로 다른 전공의 Agent가 함께 상호작용할 수 있는 기본 접점이다. Event Master는 실제 수강 여부를 AgentSummary가 아닌 AcademicScheduleSnapshot에서 읽는다.

학생의 관심 분야 후보:

- 변환 마법
- 방어 마법
- 마법약
- 마법 생물
- 고대 마법
- 마법 도구 제작

관심 분야는 별도의 공식 소속이 아니며, Agent의 학습 행동, 대화 주제, 시험 성적, 교수와의 관계에 영향을 주는 선호값으로 사용한다.

### 3.3 학년 구성

| 학년 | 학생 수 | 비고 |
| --- | --- | --- |
| 1학년 | 2명 | User Persona Agent 1명 포함 |
| 2학년 | 1명 | |
| 3학년 | 1명 | |
| 4학년 | 1명 | |

User Persona Agent는 MVP에서 1학년으로 고정한다.

### 3.4 성별 구성

기본 Student Agent 4명은 남성 2명, 여성 2명으로 구성한다.

User Persona Agent의 성별은 사용자가 시뮬레이션 시작 전 선택할 수 있다. 성별은 Agent의 행동과 관계 변화를 직접 결정하는 성격 요소로 사용하지 않는다. 다만 MEETING, 고백과 같은 일부 관계 이벤트의 조건이나 Agent의 개별 선호 설정에 제한적으로 사용될 수 있다.

### 3.5 공간과 소속의 구분

MVP에서는 공간과 조직 소속을 구분한다.

교실, 식당, 도서관, 연구실, 기숙사는 Agent가 이동하고 상호작용하는 공간이다. 해당 공간을 이용한다고 해서 별도의 조직에 가입한 것으로 처리하지 않는다.

## 4. 이벤트 시스템

이벤트는 특정 Tick에 하나 이상의 Agent가 참여하여 상태, 관계, Memory 또는 학사·소속 관련 값에 변화를 발생시키는 시뮬레이션 단위이다.

### 4.1 이벤트 종류

| 이벤트 타입 | 설명 | 주요 영향 |
| --- | --- | --- |
| CLASS | 교수가 진행하는 정규 수업 | 학습 및 피로도 관련 상태 변화 |
| GROUP_PROJECT | 지정된 Agent가 함께 수행하는 조별 과제 | 조원 간 친밀도·신뢰도·경쟁 변화 |
| EXAM | 학사 일정에 따라 진행되는 시험 | 성적 및 장학금 결정 |
| MEETING | 과팅, 미팅 등 관계 형성을 위한 만남 | 호감도 및 관계 종류 변화 |
| MT | 다수의 Agent가 참여하는 단체 활동 | 전체 친밀도 상승 및 추가 사건 발생 가능 |
| FESTIVAL | 학교 또는 소속 단위로 진행되는 축제 | 소속과 관계에 광범위한 변화 |
| STUDENT_COUNCIL | 3단계부터 활성화하는 총학생회 활동 및 관련 행사 | 소속·명성·상벌점 변화 |
| RANDOM_INCIDENT | 폭발, 실종, 저주, 마법 오작동 등 예측 불가능한 사건 | 긴장도, 상태 및 관계 변화 |

RANDOM_INCIDENT의 세부 사건은 subtype으로 구분한다. 예: MAGIC_MALFUNCTION, DISAPPEARANCE, CURSE, EXPLOSION.

### 4.2 이벤트 발생 방식

| 구분 | 설명 | 예시 |
| --- | --- | --- |
| 예정 이벤트 | 시간표 또는 학사 일정에 따라 지정된 Tick에 활성화 | CLASS, EXAM, MT, FESTIVAL |
| 동적 이벤트 | 현재 World State를 바탕으로 Event Master가 생성 | MEETING, 갈등, 고백, 화해 |
| 마법 특수 사건 | Magic Layer가 생성하는 세계관 특화 사건 | 마법 오작동, 실종, 저주, 폭발 |

Event Master가 생성하는 동적 이벤트는 Tick당 최대 1개로 제한한다.

처리 순서·참여 규칙·충돌 처리·결과 처리 상세 → `docs/03-system-design/event-master.md` 참조

## 5. 관계 시스템

### 5.4 소속 효과

같은 소속 Agent는 상호작용 기회가 증가하며 관계 변화가 더 자주 발생한다.

1단계는 전공, 2단계는 전공·동아리, 3단계는 전공·동아리·기숙사 조직·총학생회를 대상으로 적용한다. 친밀도 증가량은 추후 결정한다.

## 9. 집단 대표성 설계

### 9.1 대표성 기준

| 차원 | 내용 | 시스템 영향 |
| --- | --- | --- |
| 성격 | 개방성, 성실성, 외향성, 우호성, 정서 안정성 | 행동 선택과 감정 변화 |
| 가치관 | 성취, 협력, 규칙, 자유 중 무엇을 우선하는지 | 사건에 대한 입장과 갈등 발생 |
| 학년 | 1~4학년 | 선후배 관계와 권력 차이 |

### 9.2 기본 Student Agent의 대표 역할

| Agent 유형 | 대표 가치 | 갈등 가능성이 높은 대상 | 협력 가능성이 높은 상황 |
| --- | --- | --- | --- |
| 성취 경쟁형 | 성적, 장학금, 인정 | 사교 협력형, 자유 탐험형 | 시험, 경쟁형 과제 |
| 사교 협력형 | 관계, 공동체, 조화 | 성취 경쟁형 | 조별 과제, MT, 화해 |
| 신중 원칙형 | 규칙, 안전, 책임 | 자유 탐험형 | 수업, 사고 수습 |
| 자유 탐험형 | 자율, 변화, 새로운 경험 | 신중 원칙형 | 축제, 랜덤 사건 탐색 |

### 9.3 User Persona Agent의 역할

User Persona Agent는 사용자가 설정한 성격이 기존 집단에 어떤 변화를 발생시키는지 확인하기 위한 가변 구성원이다.

### 9.4 대표성 유지 규칙

1. 기본 Student Agent 4명은 서로 다른 대표 유형을 각각 하나씩 가진다.
2. 대표 유형의 핵심 성격 수치는 지정된 범위 안에서 랜덤 생성한다.
3. 모든 기본 Student Agent가 동일한 높은 성격 수치를 가지지 않도록 제한한다.
4. 학년은 1학년부터 4학년까지 한 명씩 배정한다.
5. 기본 Student Agent의 성별은 남성 2명, 여성 2명으로 구성한다.
6. 관심 마법 분야가 한 종류에만 집중되지 않도록 분산 배정한다.
7. 생성에 사용된 랜덤 시드와 초기값을 저장하여 동일한 조건의 시뮬레이션을 다시 실행할 수 있도록 한다.

### 9.5 MVP 이후 확장

| 개발 단계 | Student Agent | Professor Agent | 생활 Agent 총합 | 조직 범위 |
| --- | --- | --- | --- | --- |
| 1단계 MVP | 5명(User Persona Agent 1명 포함) | 1명 | 6명 | 전공 |
| 2단계 | 10명 | 3명(전공 + 교양) | 13명 | 전공 + 동아리 |
| 3단계 | 20명 | 5명(전공) | 25명 | 전공 + 동아리 + 기숙사 조직 + 총학생회 |
