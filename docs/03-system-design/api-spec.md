### 1.3 공통 응답 형식

**성공**

```json
{
  "data": { },
  "meta": { }
}
```

`meta`는 **리소스 자체의 속성이 아니라, 응답을 다루는 데 필요한 부가 정보**만 담는다. 리소스 속성이면 `data`로, 응답 처리용 정보(페이지·개수·추적 ID)면 `meta`로 — 이 기준으로 가른다. 목록 조회처럼 필요할 때만 채우고, 단건 조회 등 쓸 게 없으면 `meta` 자체를 생략한다(빈 객체로 남기지 않는다).

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `next_cursor` | string \| null | | 목록 조회 시. 다음 페이지 커서. 마지막 페이지면 `null`. |
| `has_more` | boolean | | 목록 조회 시. 다음 페이지 존재 여부. |
| `total_count` | int | | 목록 조회 시, 전체 개수 제공이 필요할 때만(연산 비용 있으면 생략 가능). |
| `request_id` | string | | `error.trace_id`와 동일 개념. 성공 응답에서도 추적이 필요하면 포함. |
| `server_time` | string | | 클라이언트-서버 시각 차이 보정이 필요할 때만. |

**실패**

```json
{
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "사용자를 찾을 수 없습니다.",
    "field": "user_id",
    "fields": ["start_date", "end_date"],
    "trace_id": "req_9f8a2b1c"
  }
}
```

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `code` | string | ✓ | 기계가 분기하는 값. 변경 시 파괴적 변경으로 취급한다. |
| `message` | string | ✓ | 사람이 읽는 값. 클라이언트가 이 값으로 분기하지 않는다. |
| `field` | string | | 원인이 **단일 입력 필드**일 때만 포함 (400/422). 그 외(404/409/500 등 리소스·상태·서버 문제)엔 생략한다. |
| `fields` | string[] | | 원인이 **여러 필드 간 관계**일 때만 포함(예: 종료일이 시작일보다 빠름). `field`와 동시에 쓰지 않는다. |
| `trace_id` | string | ✓ | 서버가 생성하는 요청 추적 ID. 로그 조회용이며 사용자에게 노출해도 되지만 클라이언트가 파싱하지 않는다. |

작성 규칙: `field`/`fields`는 "사용자가 화면의 어느 입력 칸을 고치면 해결되는가"에 답할 수 있을 때만 채운다. 답할 수 없는 에러(404, 409, 422의 상태 충돌, 500)는 비워둔다.

### 1.4 에러 코드

| HTTP | code | 의미 | 클라이언트 대응 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 요청 형식 오류 | 입력 수정 |
| 401 | `UNAUTHENTICATED` | 토큰 없음/만료 | 재인증 |
| 403 | `FORBIDDEN` | 권한 없음 | 재시도 무의미 |
| 404 | `RESOURCE_NOT_FOUND` | | |
| 409 | `CONFLICT` | 상태 충돌 | 현재 상태 재조회 |
| 422 | `BUSINESS_RULE_VIOLATION` | 형식은 맞으나 규칙 위반 | |
| 429 | `RATE_LIMITED` | | `Retry-After` 후 재시도 |
| 500 | `INTERNAL_ERROR` | | 재시도 가능 |

작성 규칙: 400과 422를 구분한다. 전자는 클라이언트 버그, 후자는 사용자에게 보여줄 메시지다.

### 1.5 페이지네이션

| 방식 | 커서 기반 |

* `cursor`는 불투명 문자열이다. 클라이언트가 파싱하지 않는다.

* `POST` 중 재시도 위험이 있는 엔드포인트는 `Idempotency-Key` 헤더를 받는다.
* 동일 키 재요청 시: 최초 응답을 그대로 반환
* 키 보존 기간: (미결)

| 대상 | 한도 | 응답 헤더 |

### 1.9 버전 정책

* 버전 위치: URL 경로 (`/v1`)
* **파괴적 변경**: 필드 삭제·이름 변경, 타입 변경, 필수 조건 추가, enum 값 삭제, 에러 code 변경
* **비파괴적 변경**: 선택 필드 추가, enum 값 추가(클라이언트는 미지의 값을 무시해야 함)
* 폐기 절차: `Deprecation` 헤더 → 공지 → N개월 후 제거
